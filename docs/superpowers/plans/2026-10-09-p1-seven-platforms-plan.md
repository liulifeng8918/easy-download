# 易下载 P1 七平台实施计划

## 目标

在不影响 P0（抖音、YouTube、哔哩哔哩）的前提下，接入小红书、微博、西瓜视频、TikTok、Instagram、Facebook、X 的统一下载路径，并建立可验证的平台状态。

## 任务 1：平台策略与状态模型

- 在站点策略表中登记七个平台的主域名和短链接域名。
- 增加人类可读的支持状态字段，初始为 `pending`。
- 保留明确不支持平台的拦截逻辑。
- 增加测试，确认恶意子域名不会误匹配。

## 任务 2：错误分类与平台提示

- 把引擎输出分类为：不支持、需要登录、需要代理、访问受限、画质不可用、视频不可用、下载失败。
- 错误提示带平台名称，但不把所有失败都说成需要登录。
- 对海外平台在未配置代理时给出代理建议；代理已配置时不重复提示设置。
- 对需要登录的场景提示用户先确认浏览器能播放，再使用已有连接浏览器入口。

## 任务 3：输入与统一路由回归

- 为七个平台增加纯链接、短链接和带额外文字的分享文案测试。
- 保证多链接、账号密码、本机地址和危险协议仍被拒绝。
- 保证未知域名仍可以尝试通用引擎，但不会显示为已验证平台。

## 任务 4：引擎与文件核验回归

- 为公开测试 URL 运行 `links/check`，记录解析结果和失败原因。
- 对成功下载的文件运行 FFmpeg 流核验。
- 记录登录墙、地区限制、代理限制和页面结构变化，不将其误记为代码通过。

## 任务 5：文档与交付

- 新建 `docs/superpowers/verification/2026-10-09-p1-seven-platforms-progress.md`。
- 每个平台单独记录状态、测试链接类型、代理条件、输出文件证据和限制。
- 所有代码测试通过后再构建新的便携包；未完成的平台继续显示“暂未通过”。

## 验收门槛

平台只有同时满足以下条件才能标记为 `verified`：

1. 公开链接可解析；
2. 真实下载生成目标媒体文件；
3. 文件包含可读取的视频或音频流；
4. 下载记录保留原始页面 URL；
5. 错误和登录/代理提示可操作且不误导。
