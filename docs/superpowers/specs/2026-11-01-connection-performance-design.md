# Chrome 引导与下载性能改造（用户已确认）

## 范围

保持免费单个下载不限次数、VIP 权限、现有 Chrome 凭据和网站访问边界不变。首次安装扩展仍需用户在 Chrome 本人确认；不使用静默安装、浏览器安全开关或自动导入全部登录态。

## Chrome

连接向导保留为后台配对载体，扩展管理页最后打开并置于前台。向导和软件设置都明确给出“开发者模式 → 加载已解压扩展 → 选择文件夹”的截图。提供直接打开扩展页、复制准确文件夹路径的按钮，路径可粘贴到文件选择窗口地址栏。已安装用户沿用自动配对，不需要输入连接码。向导本机操作端点只接受有效短期票据和受限动作，拒绝跨站请求。

## 性能与机器阈值

每次任务启动采样 CPU 和 Windows 可用内存。逻辑 CPU 不超过 2 或可用内存不足 1 GiB：总分片预算 1；CPU 不超过 4、可用内存不足 3 GiB 或内存无法识别：预算 2；其余预算 4。同时下载任务共享这个预算，资源不足的任务排队；不对每个任务各开一份预算。已有任务不强杀，内存下降只影响随后任务。这里是保守资源上限，不声称能精确预测每台电脑的极限。

HLS/DASH 使用预算内并发；已验证站点的 HTTP 下载使用 1–4 MiB 分块，其他站点保留原生兼容策略。网络/分片错误可再以单分片、无 HTTP 分块重试一次；登录、验证码、403、DRM 不靠重试绕过。手动指定的网络线路绝不擅自更改，自动模式国内直连、已登记海外平台按已保存代理。免费版也享有上述优化。

普通网站预检结果短期保存在引擎内存，以随机一次性凭据关联同一链接、画质和网络设置，下载复用原始元数据而不再次请求网页。凭据不含 Cookie；缓存到期/设置不匹配时重新解析。原始媒体地址不返回界面和日志。

任务展示排队、解析、下载、合并、快速检查等阶段，以及下载速度、剩余时间、线路、分片并发。原生下载返回成功、文件实际存在、路径受限且快速检查通过后才标记完成。

## 文件检查

默认快速检查：路径/大小、实际容器和时长、首尾各约 1 秒声画解码，验证应有的声音和目标时长；不声称检测了所有中段损坏。用户可对已完成任务手动“深度检查”，整段解码并显示单独结果。快速检查限制并发，深度检查不阻塞下载完成提示。关闭软件时结束本程序启动的检查进程，不影响外部 FFmpeg。

## 实施与验收

1. 新增独立资源预算模块及低/中/高配置单元测试，验证共享预算和失败降级。
2. 引擎实现复用预检、结构化进度、分块策略；冻结 EXE 增加新代码门禁。
3. 实现快速/手动深度检查，测试假媒体、缺音轨、错误时长、越界路径和正常视频。
4. Chrome 向导实现截图、真实入口和路径复制，验证一次性配对及旧连接兼容。
5. 回归 UI、真实扩展弹窗文档、抖音与 YouTube 完整下载；测试结果分别记录解析、传输、校验，不把分块测速当成成品通过。
6. 以 1.0.2 输出无个人数据的绿色 ZIP 和更新包，保持原主 EXE 不变以避免无谓改变 Windows 信任；逐文件清单校验。保留旧版和备份，不清理用户下载。
