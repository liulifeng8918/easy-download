# 易下载：统一下载入口与主流网站内部适配规格

日期：2026-10-08

状态：用户已确认统一操作与验证窗口边界；已补入主流网站资料及处理矩阵，待复核新增范围，尚未实施。

配套资料：[主流视频平台兼容矩阵与一手资料](2026-10-08-mainstream-video-compatibility-research.md)。其中的平台路线、限制、优先级和验收要求属于本规格的一部分，不是独立的“全部支持”宣传名单。

## 1. 产品目标与已确认边界

普通用户统一操作：粘贴链接或完整分享文案 → 选择画质 → 点击下载。

不同网站的链接提取、解析、正常网页初始化、必要请求信息与下载方式，由程序内部处理。普通抖音下载不要求安装扩展、填写域名、复制令牌或手动播放完整视频。

仅网站确实要求登录或验证码时，显示易下载内部的网站验证窗口；验证完成后自动继续同一个任务。关闭验证窗口即取消本次解析，不循环弹出设置页。

不承诺所有网站、所有抖音内容或最高源画质可用。不绕过验证码、私人内容访问权限、付费限制或 DRM。

本轮覆盖 23 个常见平台的设计处理规则，以及陌生网站兜底；覆盖处理规则不等于 23 个平台均已集成或实测通过。首发聚焦单条视频和已结束的回放，不新增直播录制、主页批量下载、图片笔记下载或自动购买会员。

## 2. 现有代码与证据

- 主进程：`electron/main.cjs`；预加载：`electron/preload.cjs`。
- 当前界面：`electron/renderer/app.html` 与 `electron/renderer/ui.js`。
- 后端：`python/easy_download_sidecar.py`；下载引擎：`python/download_engine.py`。
- 当前前端直接执行 `new URL(整个输入)`，完整分享文案会在解析前被拒绝。
- 已有浏览器实验通过正常抖音播放页获取视频媒体地址，保存了约 57.47 秒、含视频与音频的 MP4，并通过完整解码检查。这是路线可行性证据，不是易下载集成验收。
- 实际发布外壳中的隐藏网页行为、当前新分享链接、画质选择与端到端任务尚待验证。

## 3. 分享文案解析规则

### 用户提供的验收样例

输入：

> 9.79 07/31 :3pm jcn:/ w@S.LJ 从王二到闯王，明末农民起义拉开帷幕！ # 明朝 # 明末 # 崇祯  https://v.douyin.com/uOCeLrzmht8/ 复制此链接，打开Dou音搜索，直接观看视频！

必须提取：

`https://v.douyin.com/uOCeLrzmht8/`

### 规则

1. 接受纯网址，以及包含一个 HTTP/HTTPS 网址的分享文字；不要求用户手动删除前后文案。
2. 由主进程中的独立、可单测模块提取并校验，供下载入口统一调用。界面不保留另一套会拒绝分享文案的前置网址校验；后端继续校验收到的规范化网址与请求格式。
3. 清理链接外围空白、外围不可见字符和不属于链接的中文标点；正确处理链接被引号或括号包围的情况。
4. 保留网址大小写敏感的路径、合法百分号编码、查询参数和签名参数；不整体改写或解码网址，不删除必要字符。
5. 相同链接重复出现只算一个。出现多个不同链接时提示“检测到多个链接，请每次下载一个”；本次不新增批量下载功能，也不猜测应下载哪个。
6. 无链接、残缺网址、不支持的协议或含账号密码的网址明确拒绝；文案中的版本号、时间、标签和口令不是网址。
7. 输入最大 20,000 字符；超限给出简明提示。
8. 提取成功后，输入框显示规范化网址，提示“已识别分享链接”；下载记录使用视频原始页面网址，不显示临时 CDN 签名地址。

## 4. 内部处理结构

统一入口按以下顺序工作：

1. 提取分享文案中的网址并校验。
2. 检查真实许可证状态；未激活时不启动站点解析和下载。
3. 选择内部站点适配器。
4. 完成解析或必要的网站验证。
5. 将受控解析结果交给本地下载队列。
6. 核验实际输出媒体后反馈结果。

### 通用适配器

保留 YouTube 等已正常网站的现有下载引擎、代理设置、Cookie 辅助能力、画质选择、输出目录和更新功能。普通用户不需要知道适配器名称。

### 统一路由与站点策略

按以下确定顺序处理，避免同一网站无限切换解析方法：

1. 分享文案提取及已知短链接展开，保留签名、访问令牌和分 P 等有效参数。
2. 已核验的媒体直链：交由文件／播放清单下载器，检查媒体类型，不能把任意 HTML 当视频。
3. 已登记站点：使用该站点策略。抖音采用内部浏览器路线；YouTube、B站等优先使用专用解析器。
4. 专用解析器失败时，只有登记了且实际验证过的浏览器适配器才能尝试一次网页路线；不以“浏览器能播放”作为万能兜底。
5. 陌生网站：尝试通用静态页面解析和已有嵌入播放器解析；没有可靠目标媒体时提示暂不支持。用户添加域名不会凭空新增解析能力。
6. 所有路线共用真实授权校验、错误分类、任务队列、代理策略、结果核验和隐私规则。

站点注册表明确保存域名／短链接别名、接受的页面类型、首选适配器、允许的浏览器后备、登录状态来源、媒体域名策略、网络策略、画质／分段能力、限制及验证状态。站点判定使用解析后的域名，不用字符串包含匹配。

每个适配器提供统一解析结果：来源页面、视频身份、标题、可用画质、媒体流／清单、必需请求头、会话引用、合理预期时长、是否直播／试看／DRM、媒体有效期和可执行的错误状态。敏感字段只留在受控本地进程，不交给界面展示。

MP4、非 DRM 的 HLS 和 DASH 由已有本地引擎处理；DASH 分离音视频需合并。`blob:`／MSE 对象不是可转交给后端下载的 HTTP 文件地址，必须通过站点适配器获得目标的真实流／清单；不能承诺下载任意 `blob:`。

### 主流站点的专项要求

- YouTube：随包核验 Node 与外部 JS 解题脚本，匿名公开视频优先；网站 PO 校验、年龄限制、私有／会员访问与网络错误分别处理，不让用户填写底层技术令牌。
- B站：支持单条视频与分享短链接，保留当前分 P；处理音视频分离、登录后新增画质及会员限制，不能用低画质冒充用户指定画质。
- 小红书：保留分享链接的 `xsec_token` 等参数；仅视频笔记属于当前下载目标。
- 微博、西瓜、TikTok、Vimeo、Instagram、Facebook、X、Dailymotion、Twitch 回放、AcFun、搜狐：按矩阵设置专用解析、验证与媒体处理；未实测的浏览器后备不启用。
- 快手、好看视频：目前资料不足以证明现包有可用专用路径，列为单独适配／验证项，不假装“登录即可下载”。
- 腾讯视频、爱奇艺、优酷、芒果TV、Viu：只尝试当前访问权限内的非 DRM 内容，区分正片、预告和试看；只有试看时说明“仅可获取试看”，不能标作整集完成。
- Viu 源码存在修改试看时长的回退分支，不能不加审查地复用默认路线；适配器不得触发取消未授权试看限制的尝试。无法确认当前账号正片访问资格或无法隔离该分支时，该目标直接返回限制说明。
- Netflix：本版不提供正片提取；给出官方离线观看渠道提示。

详细网址类型、路线、限制与来源见兼容矩阵。

### 网络与登录兼容

- 代理只是网络路径，不提供网站账号、会员资格或解析能力。当前网络已可访问时不强制使用代理。
- 在已有自动代理模式下，网站策略提供默认选择；已检测到网络连接失败且存在有效本机代理时可切换网络路径重试一次。保留用户主动选择的“直接连接”或自定义代理，不在后台覆盖。
- 不凭网站属于“海外”就把任何错误归为需要代理；单独处理地区限制和服务不可见，也不承诺切换代理可解除限制。
- 一次解析与文件下载保持一致的网络／会话上下文；Cookie、临时链接或网页校验可能与网络路径相关。
- 真正登录或验证码时优先内部网站窗口。主流平台的嵌入登录能力必须逐站验证，不能承诺所有账号都能在 Electron 登录。
- Google OAuth 政策禁止开发者控制的嵌入式授权请求；这不等于所有 YouTube 网页登录均被证明不可用。YouTube 不接入已被引擎文档注明不可用的 OAuth 登录路线。
- 如果实际站点不接受内部验证，明确返回“当前版本无法完成该网站验证”，而不是反复弹设置。本版不新增未验证的系统浏览器自动接回机制；已有可用授权辅助能力保留为可选高级功能。

### 抖音适配器

- 识别精确的抖音网页域名和短链接域名，不用字符串包含判断域名。
- 在隔离的 Electron 浏览器会话中加载正常播放页，解析短链接跳转到的视频页面。
- 静音、短暂初始化播放器，等待目标视频媒体地址就绪；不要求完整观看，不录屏，不等待整段缓存。
- 校验解析后的视频身份与原始链接一致；不能误取推荐视频、广告或其它节点的媒体。
- 取得资源后结束浏览器解析工作，使用下载队列保存完整文件。
- 媒体解析结果通过受控内部接口传给后端，包含原始页面网址、媒体地址、必要的请求信息、适配来源和画质信息；不把临时地址或 Cookie 返回给界面展示。
- 如果下载需要浏览器会话信息，只传递目标请求必需的信息，不读取或转移其它网站的登录状态。
- 临时媒体地址过期时最多重新解析一次；仍失败则给出具体原因，不无限重试。

普通解析设定有界超时，建议默认 45 秒。一次只运行一个抖音浏览器解析，后续解析排队；已有文件下载可以继续。验证等待默认最多 5 分钟，并允许用户关闭窗口取消。

## 5. 网站验证与错误反馈

真正出现登录页或验证挑战时，显示对应的网站验证窗口；用户正常完成后，程序重新检查目标视频并自动继续。

仅出现 HTTP 403、解析接口失败或笼统的 Cookie 相关错误，不能直接认定为“用户没有登录”。应区分：

- 正在识别链接／解析视频；
- 等待网站验证；
- 下载中；
- 链接失效或视频不可见；
- 网络连接失败；
- 网站当前限制了访问；
- 当前页面暂不支持；
- 用户取消；
- 需要视频密码；
- 当前版本无法完成该网站验证；
- 地区限制；
- 仅能获取试看或预告；
- DRM／无访问权限；
- 正在直播或输入的是图片笔记／主页；
- 下载完成但未生成有效媒体文件。

抖音普通流程不跳转到扩展设置页。现有扩展作为其它网站或高级场景的可选辅助保留，不删除用户已经使用的功能。

## 6. 安全与生命周期

- 外部网站窗口启用沙盒、上下文隔离，关闭 Node 集成，不加载主界面的特权预加载脚本。
- 网站不能调用本地授权、文件系统、下载设置或任意主进程接口；禁止任意弹窗与不必要的设备权限。
- 抖音页面导航及媒体跳转限于该适配器允许的目标，拒绝非 HTTP/HTTPS、本机与私有网络目标、嵌入凭据和异常重定向。
- 登录状态保存在本机独立会话，不上传我们的授权后台，不导出用户 Chrome 全部 Cookie；程序正常访问网站仍按网站自身登录流程进行。
- 日志不记录 Cookie、配对令牌、授权密钥或完整的临时签名媒体地址。
- 主窗口关闭时释放隐藏解析窗口和未完成解析，随后按原逻辑退出；隐藏窗口不能导致软件退出不了。
- 显示验证窗口不应改变应用单实例和主窗口聚焦逻辑。
- 解析与下载都维持后端许可证校验，本次不改动激活协议和业务有效期。

## 7. 画质与结果核验

- “最佳画质”表示当前路线可以获取的最高可用画质，不将网页默认清晰度冒充网站最高源画质。
- 指定画质不可用时明确说明，不能无提示换成其它画质。
- 音频模式保留现有音频提取功能。
- 只有实际媒体输出通过核验才标记成功：检查文件存在、非空，使用随包提供的 FFmpeg 检查媒体类型、音视频流和合理时长；网页、错误页和空文件不能标记成功。
- 端到端验收至少对样例输出做完整解码，证明文件完整且可播放；不把 HTTP 成功或任务创建成功当作下载成功。
- 下载检测成功必须含可用的目标媒体／清单，不仅检查解析进程返回码。核验格式、预期时长、音视频关系和非试看目标；原内容本来无音频的情况不应强制判失败。
- 同一规范化来源／当前分 P、画质和输出目录的进行中任务去重，重复点击提示“该视频已在下载”；不同画质或不同目标不能误合并。

## 8. 打包原则

- 优先保留用户已经确认能启动的旧版 Electron 外壳字节，仅更新必要应用资源。
- 后端实现需要更新随包运行组件时如实说明并重新验收；不承诺所有电脑都不会受 Windows 安全策略影响。
- 分发包不包含开发机许可证、浏览器会话、Cookie、下载历史、私钥或 Developer Key。
- 清洁用户数据环境必须首次要求激活；升级已有包不得破坏用户正常许可证和设置。
- 本项目当前没有 Git 仓库，规格保存为文件；不为满足文档流程自行初始化或提交另一个项目的仓库。

## 9. 验收清单

### 单元与安全检查

- 用户提供的整段抖音分享文案准确提取上述唯一网址。
- 纯短链接、长播放链接、换行、中文标点、引号括号、查询参数与百分号编码。
- 无链接、不同的多个链接、重复链接、超长文案、危险协议、伪装域名和私有地址拒绝情况。
- 目标视频身份匹配、解析超时、用户取消、媒体地址过期和许可证失效。
- 403 不误弹“需要登录”的设置流程。

### 实际发布程序端到端

- 在实际准备交付的绿色版里测试，不仅使用 Codex 浏览器或开发环境。
- 使用用户此次分享文案作为首个样例；另测试至少两条正常可访问的抖音链接，覆盖短链接与长链接。
- 至少一个公开视频在清洁会话中无需扩展即可完成；真实登录或验证码出现时在内部窗口完成后续流转。若测试期间未出现真实挑战，应如实标注该分支未实测。
- 下载文件的视频身份正确、时长合理、音画可读且完整解码通过。
- YouTube 等已经正常的网站、音频下载、输出目录选择、清空记录、设置、激活与退出做回归。
- 验证绿色包可启动、未激活不可下载、不继承开发机激活与登录状态。
- 每个平台用合法可访问的具体样例记录实际包版本、引擎版本、网络方式、登录状态、网址类型、画质、输出身份／时长／解码和结果日期。仅通过单个样例不能宣称全站支持。
- 登录、密码、地区、试看和 DRM 分支未触发实测时，如实记录为未实测，不能用模拟测试冒充平台验证。

## 10. 实施次序

1. 分享文案提取与统一入口：先以离线单测验证规则。
2. P0：YouTube、B站回归及抖音最小闭环；用实际外壳证明完整媒体下载。共享错误／媒体核验／验证窗口与任务生命周期在此完成。
3. P1：复用现有专用解析器验证微博、小红书、西瓜、TikTok、Vimeo、Instagram、Facebook、X、Dailymotion、Twitch 回放、AcFun；不为未通过样例增加宣传承诺。
4. P2：快手、好看视频单独适配，以及搜狐／腾讯／爱奇艺／优酷／芒果／Viu 的条件内容；本轮先统一识别和准确失败反馈，不因此无限推迟首发。
5. 陌生网站非 DRM 媒体及嵌入播放器回归、清洁分发打包和用户样例验收。

若实际外壳无法取得可用目标媒体，停在实验证据阶段，报告真实限制；不能仅因浏览器实验成功就宣称新版可用。

## 11. 面向用户的支持表述与维护

建议使用：

> 粘贴视频链接或完整分享文案，易下载会自动识别并检查。可下载的视频会进入任务列表；需要网站验证时会给出明确提示。受账号权限、地区、网站限制或加密保护影响的内容可能无法下载。

界面只显示当前视频结果与下一步，不要求用户查看解析器名单、配置技术令牌或判断播放清单类型。可展示网站级验证记录，但必须标注版本与适用范围；资料已查到不显示为支持成功。

站点变化按独立适配器和测试样例维护；记录组件版本、验证日期与回归结果，失败不自动改写已验证的外壳或降级安全规则。更新沿用现有入口和包校验，不在本次设计中额外引入第三方云解析服务或付费大模型。
