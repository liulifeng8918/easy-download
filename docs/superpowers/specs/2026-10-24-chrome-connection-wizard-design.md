# 易下载两步连接 Chrome 设计规格

日期：2026-10-24

## 目标

把普通用户连接 Chrome 的流程从“打开扩展文件夹、复制连接码、填写域名、保存同步”压缩为两步：

1. 在易下载点击“连接 Chrome”，程序自动打开 Chrome 扩展管理页、连接向导页和扩展文件夹。
2. 用户在 Chrome 中点击“加载已解压的扩展程序”并选择已打开的 `extension` 文件夹。

扩展加载后自动与本机易下载完成一次性握手，自动保存桥接凭据、发现已登记平台并同步登录状态。普通用户不再看到连接码、Cookie 数量或域名文本框。

## 方案边界

- 不发布 Chrome Web Store，不尝试静默安装或绕过 Chrome 安全确认。
- 保留手动安装和重新连接作为“高级设置”备用路径。
- 普通公开视频不触发连接向导；仅在下载结果要求登录时引导连接。
- 扩展只访问易下载内置的平台范围；发现的平台以标签显示，用户可以删除。
- 配对票据一次性、短时有效，仅在本机回环接口使用；桥接凭据不写入页面文本或日志。

## 用户界面

设置页的主卡片只显示：

- 状态：未连接 / 正在连接 / 已连接 / 需要重新连接
- 主按钮：连接 Chrome
- 已发现网站标签：可删除
- 次按钮：重新同步
- 高级设置：手动安装扩展、查看 PDF 手册

下载失败且错误属于登录要求时，操作按钮显示“连接 Chrome 并重试”。

## 配对流程

1. 渲染进程调用 `connectChrome` IPC。
2. 主进程创建 10 分钟有效的一次性 setup ticket，并启动本地连接向导页面。
3. 主进程打开 Chrome 的 `chrome://extensions` 和向导页，同时打开扩展目录。
4. 用户加载未解压扩展。
5. 扩展在安装或启动时检查向导页，读取 ticket 并向本机桥接端点请求配对。
6. 主进程校验 ticket、返回当前桥接凭据并立即使 ticket 失效。
7. 扩展保存凭据，使用内置平台列表执行发现和同步。
8. 主程序轮询状态并显示“已连接”，必要时自动重试原任务。

## 错误处理

- Chrome 未找到：显示“请手动打开 Chrome”，并保留打开扩展文件夹按钮。
- 用户取消加载扩展：向导保持等待，不显示技术错误。
- ticket 过期：显示“连接已过期，请重新点击连接 Chrome”。
- 扩展版本过旧：显示“请重新打开当前版本扩展文件夹”。
- 网站权限未允许：只提示需要允许已登记平台权限，不显示 Cookie 细节。

## 验证

- 源代码检查：主进程、预加载、渲染脚本和扩展脚本通过语法检查。
- UI smoke：连接卡片、状态变化、手动安装备用入口和登录失败引导可用。
- 单元测试：配对 ticket 单次使用、过期、错误 ticket 和旧手动凭据兼容路径。
- 打包验证：安装目录版和绿色版均包含向导页面、扩展和 PDF 手册。
