# 易下载 P1 七平台兼容设计规格

日期：2026-10-09
状态：已获用户确认，待实施计划

## 1. 目标与范围

本批扩展以下七个平台：

- 小红书
- 微博
- 西瓜视频
- TikTok
- Instagram
- Facebook
- X（Twitter）

AcFun 不纳入本批，后续单独验收。YouTube、哔哩哔哩、抖音保持 P0 路线不变。

本批目标不是把七个平台全部标记为“已支持”，而是建立真实可验证的逐平台状态：只有公开链接解析、实际媒体下载、文件存在性和 FFmpeg 媒体核验全部通过，平台才可以显示“已支持并验证”。

## 2. 用户体验原则

用户仍只需要粘贴链接或分享文案并点击“开始下载”。平台差异由程序内部处理。

失败提示按原因区分：

- `需要登录`：解析器明确收到登录墙、私密账号或登录 Cookie 不足；
- `需要代理`：页面或媒体域名在当前网络不可达，且程序检测到可用代理配置；
- `暂未通过`：平台已登记，但当前路线尚未完成真实验收；
- `解析失败`：链接有效，但当前页面结构、地区限制或视频权限导致无法取得媒体；
- `下载文件无效`：进程返回但没有生成可核验的视频或音频文件。

不能把所有失败统一显示为“请登录”，也不能把“yt-dlp 能识别”直接显示为“支持”。

## 3. 架构设计

### 3.1 平台策略登记

继续使用站点策略表登记平台名称、域名、适配器、优先级和验证状态。七个平台初始状态为 `pending`，适配器先走 `engine`，不新增浏览器 Cookie 桥接。

策略表只负责路由与文案，不代表实际可用性。未知域名仍可由通用引擎尝试，但界面不得把未知域名显示为已支持。

### 3.2 统一解析与下载

七个平台通过现有 `/v1/links/check` 和 `/v1/downloads` 路线运行：

1. 从纯链接或完整分享文案提取唯一公开 URL；
2. 识别平台策略；
3. 使用当前代理设置调用下载引擎；
4. 根据引擎错误分类为登录、网络、地区、权限或解析失败；
5. 下载完成后由 FFmpeg 和文件检查确认媒体有效性。

不为 P1 平台复用抖音的独立浏览器解析器。若某平台实际需要浏览器登录，先记录为未通过，后续再单独设计 Cookie 授权路线。

### 3.3 平台状态

每个平台维护以下状态之一：

- `verified`：本批实际验收通过；
- `login-required`：公开链路不可用，但确认登录后可能有路线；
- `network-dependent`：需要代理或网络条件，尚未完成稳定验收；
- `pending`：已登记但尚未完成验收；
- `unsupported`：当前版本明确不支持。

初始状态全部为 `pending`，状态必须由验收脚本或人工记录显式更新。

## 4. 测试与验收

每个平台至少准备以下测试项：

- 一个公开短链接或公开详情页；
- 一个包含额外文字的分享文案；
- 代理开启和关闭各一次（若平台在本地网络可达，则记录“不需要代理”）；
- 解析结果是否为目标页面而不是推荐内容；
- 输出文件是否存在、大小大于零、包含视频或音频流、FFmpeg 能完整读取；
- 失败时是否给出平台相关但不误导的提示。

登录、私密账号、年龄限制、地区限制、直播、DRM 和付费内容不纳入“公开链接通过”标准，必须单独记录。

验收记录写入 `docs/superpowers/verification/2026-10-09-p1-seven-platforms-progress.md`，每个平台只在证据充分后更新为 `verified`。

## 5. 非目标

- 本批不开发新的浏览器扩展或 Cookie 自动同步；
- 本批不承诺下载所有账号、地区或付费内容；
- 本批不把 Netflix、Viu、快手、好看视频重新开放；
- 本批不修改许可证、激活和 P0 抖音专用解析路线；
- 本批不因为用户手动添加域名而绕过平台策略。
