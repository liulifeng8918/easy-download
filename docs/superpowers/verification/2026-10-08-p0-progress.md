## 当前完成

- 分享文案识别模块已接入主进程下载入口，用户给出的抖音分享文案可提取为 `https://v.douyin.com/uOCeLrzmht8/`。
- 同一规则保留 B站分 P、 小红书签名参数、百分号编码和短链接路径；多链接、账号密码、本机／内网、危险协议和超长内容会拒绝。
- 站点路由已登记 P0、P1、P2 和不提供正片的范围；快手、Viu、Netflix 等未验证路线不会因为用户添加域名而误调用通用下载。

- 抖音媒体候选必须是目标页面、目标视频身份、允许媒体域名、非 `blob:`、非本机地址且有合理时长；拿不到目标媒体不会下载推荐内容。
- 任务创建继续由 Python 引擎做许可证校验；未激活或周期验证失败时不会打开网站解析。
- 任务列表增加本地 FFmpeg 媒体核验，不能把 HTML、空文件、无流文件或明显时长不符的结果标记为成功。
- 重复点击同一来源／画质／目录在当前进程内去重；清空记录继续保留进行中的任务。
- 抖音浏览器解析若实际使用代理，代理路径会传递给媒体下载引擎；下载引擎不会因为媒体 CDN 与页面域名不同而错误直连。
- yt-dlp 回报路径与 Windows 长路径／Unicode 表示不一致时，仅在输出目录内恰好新增一个合法媒体文件的情况下回退识别；多文件或目录外路径仍拒绝标记成功。

## 经验总结

1. 统一用户操作不等于统一底层请求；适配器差异必须在软件内部封装。
2. yt-dlp 有解析入口不等于当前网址可下载；实际包、账号、地区、挑战、试看和 DRM 必须分别记录。
3. 播放器能播放不等于 `video.currentSrc` 可直接下载；MSE、分段、临时签名和身份匹配要单独处理。
4. Cookie 推送、网站登录状态、YouTube PO 校验和易下载许可证是四套不同机制，错误信息不能混为“请登录”。
5. 下载进程返回 0 不等于有视频；最终状态必须由文件与流核验决定。
6. 旧外壳已被用户确认可启动；本轮用清洁目录验证了完整 P0 资源链路，但发布前仍需在目标机器人工确认 Windows 安全提示与代理环境。
