## Windows 拦截证据

用户描述为“Windows 已保护你的电脑／未知发布者”。本机查到的事实：

1. 旧安装包、新主程序及下载引擎均为 `NotSigned`。当前用户和本机证书存储均无代码签名证书。
2. Defender 实时防护开启。对旧安装包及新构建目录执行本机定向扫描，均报告 `found no threats`。这不是绝对无病毒证明，也不代表其他杀毒产品或其他设备不会拦截。
3. CodeIntegrity 日志 3033/3077：23:35:16 拦截旧版引擎；23:48:07 拦截 NSIS 构建中间程序，原因是未满足签名级别/代码完整性策略。
4. 对应活动策略为 `VerifiedAndReputableDesktop`，ID `{0283ac0f-fff1-49ae-ada1-8a933130cad6}`；`VerifiedAndReputablePolicyState=1`。这是 Smart App Control 相关策略，不只是界面警告。
5. `electron-builder` 输出中的“signing with signtool.exe”不等于实际完成数字签名；应以签名验证结果为准。

未关闭安全功能，未加排除项，未修改系统策略，未绕过被阻止的程序执行。构建依赖的一处损坏文件已通过 `npm ci` 按锁文件重建。

## 0.1.2 YouTube 代理修复

- 原因：旧设置文件中的代理值为字面量 `undefined`，下载命令把它传给 yt-dlp 后被解析为 `undefined:80`。
- 修复：启动加载时将 `undefined`/`null` 恢复为 `http://127.0.0.1:7892`；保存设置时校验代理协议、主机和端口；错误值不再进入下载进程。
- 证据：使用截图中的 YouTube 链接和本机代理，内置 yt-dlp `2026.08.19` 成功读取视频标题；代理修复测试和全部 8 项 Python 测试、4 项 Node 测试通过。
- 交付：`release-0.1.2/EasyDownload-0.1.2-x64-setup.exe`，SHA-256 为 `be082298e4560033c237e0afb97c486ff05d66e57eea4dde7952e14a84f0657c`。Defender 定向扫描未发现威胁。
- 当前电脑的 Verified and Reputable 应用控制策略仍可能阻止未签名安装器启动；这与 YouTube 下载错误是两个独立问题。
